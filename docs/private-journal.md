# 心路：GitHub 加密日记

主页页脚的「心路」进入 `/journal/`。第一次使用：

1. 默认仓库是 `yutienyang/yutienyang.github.io`，也可以填另一个你拥有的私有仓库。仓库必须已初始化（至少有一个 README）。
2. 在 <https://github.com/settings/personal-access-tokens/new> 创建 Fine-grained Token：只选这个仓库，Repository permissions → Contents → Read and write，并设置有效期。
3. 在页面输入 Token 和一个至少 16 字符的强随机 key（建议密码管理器生成）。点击「打开日记」，没有文件时再次输入 key，点击「创建加密日记」。不要把 Token 或 key 发给别人或提交到代码中。
4. 点击「写一篇」，在页面编辑，点击「加密并保存到 GitHub」。看到成功提示后才表示服务器确认保存。每次保存会产生一次 GitHub 提交。
5. 其他设备打开相同页面、填写相同仓库与 key 即可读取。保存修改需要 Token；私有仓库读取也需要 Token。公开仓库可以不填 Token，只读解锁。

数据文件为仓库默认分支的 `_private/journal.enc.json`，由页面首次创建；代码中不包含默认密码或示例私密内容。`_private` 不会由 Jekyll 发布为网页，但公开仓库仍能下载密文。入口不出现在站点地图中；这个设置仅减少发现，实际保密依靠加密。

## 使用与恢复

- Token、key、明文不存入 localStorage、sessionStorage、Cookie 或仓库。Token 仅用于 `api.github.com` 请求，key 只在本机派生密钥。
- 手动锁定或闲置 10 分钟后，清空解密内容与 Token。若有未保存修改，先加密保留在当前页面的内存中，再锁定；重新输入原仓库与 key 可恢复。**刷新、关闭或离开页面会丢失这种临时草稿**，浏览器会尽可能提示。移动浏览器强制关闭进程时可能不提示。
- 「导出加密备份」包含未保存的修改。「导入备份」只能导入当前日记生成的备份（相同密钥和 salt），导入后需要显式保存。没有 GitHub 文件时，用 GitHub 网页把备份以 `_private/journal.enc.json` 路径上传到目标仓库，即可用原 key 打开。恢复时不要重新创建不同 key 的日记。
- GitHub 用文件 SHA 检查版本。并发更新、权限错误、断网不会自动覆盖其他设备的数据；失败时当前草稿保留。冲突时先导出备份，保留当前页面，在另一个标签打开最新版本核对，再选择需要保留的内容。导入是整本替换，不是自动合并。
- key 丢失后不能找回内容。Token 过期可重新生成，日记 key 不受影响。当前不提供 key 轮换或分享权限管理。

## 保密边界

使用 Web Crypto 的 PBKDF2-SHA256（600,000 次、16 字节随机 salt）派生不可导出的 AES-256-GCM 密钥，每次加密生成独立的 12 字节随机 IV，认证标签用于检测篡改。标题、日期、正文、记录 ID 一起加密。版本和加密参数公开，GitHub 能看到文件大小、提交时间、作者及提交历史。

公开仓库中的密文可被任何人下载并离线猜测 key，所以必须使用高强度 key；可以用独立私有仓库减少密文暴露。获得 key 和密文的人能读取日记；编辑仓库仍需要 GitHub 的写权限。删除记录只改变最新版本，不清除 Git 历史中的旧密文。

加密不防范已被控制的浏览器、恶意扩展或被篡改的网站代码。日记页面独立于主页布局，不加载 CDN、分析脚本或第三方脚本，CSP 只允许本站脚本和 GitHub API 连接。Token 的 Contents 写权限作用于整个选定仓库，不局限于一个文件；使用专门的私有仓库可缩小授权范围。

当前整本日记明文上限约 700 KB，保证密文处于 GitHub Contents API 的内联读取范围内。保存会更新仓库默认分支；若该分支有保护规则，则需要允许此类直接提交。若与主页使用同一仓库，保存日记可能触发 GitHub Pages 构建。
